# 股票数据采集器

输入股票名称、6 位代码，或直接粘贴东方财富页面地址即可查询。例如：

- `https://quote.eastmoney.com/f1.html?newcode=0.301307`：分时成交/逐笔页面
- `https://quote.eastmoney.com/sz300059.html#fullScreenChart`：日线页面

支持：

- 当日分时成交，数据截止到当前接口返回时间
- 当日接口可获取的成交明细，包含时间、价格、成交量和买卖方向，并核验主交易成交量；不保证交易所原始逐笔完整性
- 最近约两年日线数据，图表可切换最近 30 / 60 / 120 / 250 个交易日
- 自适应窗口的日线蜡烛图、MA5/10/20、分时价格/主交易均价线，成交量或 MACD 副图，鼠标定位查看数值
- MA、MACD、RSI、KDJ、BOLL、ATR、OBV、量比和阶段收益
- 与上证指数、深证成指或创业板指的阶段超额收益比较
- 主交易分时 VWAP、主动买卖量和净主动量；竞价快照与盘后定价单列
- 最近 31 天龙虎榜
- 走势概览：均线位置、MACD/RSI 状态、历史区间、收益与波动统计（不作买卖预测）
- 数据质量页：日期一致性、历史字段覆盖率、主交易成交量/额对账、备用来源与缺失提示
- 成交明细按买卖方向、交易阶段和最小成交量筛选
- 最近查询、股票收藏及刷新间隔自动保存；不会保存或改写原始行情
- AI 分析和追问：支持 CLIProxyAPI/OpenAI 兼容 Key 接口，以及独立的官方 ChatGPT 授权登录；固定股票和行情快照，明确标记数据缺失
- 导出日线指标 CSV、基准指数 CSV、分时 CSV、逐笔 CSV 和分析 JSON

页面地址本身是 JavaScript 展示页，HTML 只返回页面框架。逐笔数据使用东方财富 f1 页面对应的明细接口，以 `pos=0` 获取接口当天可返回的明细；如果东方财富暂时不可用，才切换到腾讯约 3 秒汇总数据，并明确标记为备用口径，不会把备用数据标成最终逐笔全量。09:25 前的集合竞价记录是行情快照，不累计为成交量；腾讯收盘汇总可能在 15:00:01 返回，另设汇总时间容差；15:05 起的盘后定价交易单独统计，15:00 至 15:05 的其他记录保留为阶段待确认。东财逐笔接口不提供精确成交额，因此“金额”保留空值，另列“估算金额”和口径，避免把估算值冒充原始值。成交量差异会明确提示，不自动修改原始成交量以制造一致。

## 运行

```powershell
cd D:\CodexProjects\eastmoney_stock_spider
python stock_spider.py
```

也可以双击 `run_stock_spider.bat`。窗口默认约 1040×700，支持缩小至 760×520，图表随窗口调整。

查询支持股票名称、代码和上面的东方财富网址。按 Enter 查询、F5 手动刷新、Ctrl+E 导出。自动刷新间隔可选 5 / 10 / 15 / 30 / 60 秒：行情与分时轻量更新，成交明细独立且至少间隔 30 秒更新；同一类正在进行的请求不会重复发起。实时更新不等待可选的东方财富精度补充请求，该精度补充保留在完整查询中；显示值始终注明实际来源。刷新间隔不是交易所零延迟保证，网络变慢时不会重叠发起请求。

日线和基准历史通过手动刷新重新采集；进入新交易日时也会自动重同步。只有主日线源已包含该交易日，才将实时价格同步到历史序列；否则暂停技术分析与导出并提示重试，避免新不复权价格接到旧复权历史。界面显示真实行情日期/时间及来源，旧交易日快照不会被标成今日实时数据。

默认导出到工程目录的 `导出数据\股票代码`，也可以自行选择目录。个人收藏和界面偏好保存于工程 `.stock_spider_state.json`，不进入 Git。

## AI 分析

先查询股票，再打开「AI 分析」页的设置。地址和模型默认留空，之后自行填写即可；未配置时行情查询、图表和导出仍正常使用。

- CLIProxyAPI 或其他兼容接口：选择接口 Key，填写服务的 Base URL、客户端 Key 和模型名。可以点击「读取模型」选择服务实际返回的模型，不猜测账号有权使用的模型。填写基础地址（通常以 `/v1` 结尾），不要填写具体 `/chat/completions` 路径。可选择 Chat Completions 或 Responses 协议。
- 官方 ChatGPT：选择官方登录，点击 `Continue with ChatGPT`，在系统浏览器中完成独立授权。使用该账号允许的模型和 ChatGPT 套餐/额度；账号、地区和工作区策略可能限制可用性，程序不绕过限制。此方式不会读取你的 Codex 凭据或浏览器 Cookie，也不会把官方令牌发到 CLIProxyAPI。
- Key 只在本次运行内存中保留，重新启动需再次填写；地址、模型及协议可保存。远程地址必须使用 HTTPS，仅本机回环地址允许 HTTP。不得在地址中嵌入 Key、账号密码或查询参数，也不要在聊天内容里粘贴密钥。
- 点击「分析当前股票」或发送追问才请求模型；自动刷新、股票查询、启动和保存设置不会自动生成 AI 回答。请求会发送可预览的行情快照和对话，可能消耗服务额度。取消只阻止旧回答进入界面，无法保证服务端停止计费；失败不自动重试。
- 当前 AI 输入包含行情、最近 120 行日线量价及最新技术指标、宽基指数、最多 300 条当日分钟记录、已取得明细的阶段/方向统计、近期龙虎榜及质量检查。不会发送数千条原始逐笔、原始错误详情、本地文件路径或导出目录；采样范围会注明。
- 对话固定到发起分析时的股票和数据截止时间。同日行情更新不悄悄改写对话，重新点击分析才更新快照；切换股票或跨交易日会清空旧会话并丢弃旧请求。长对话达到上限时需开启新分析，不会静默删掉早期事实。

官方登录的 ID Token 使用 PyJWT 验证签名、签发者、账号、客户端和有效期。需要安装依赖：

```powershell
py -3 -m pip install -r requirements.txt
```

本程序专用的登录令牌使用 Windows 当前用户保护机制加密保存在用户本地应用目录，不写进工程、导出或 Git。退出登录会尝试撤销本程序的可续期会话并清除本地令牌；若未确认远程撤销，可在 ChatGPT 设置中断开本程序。工程 Key 模式不依赖官方登录库。

AI 当前以技术行情为主；行业/概念板块、同业排名、公司公告和新闻、财务估值、资金流与融资融券仍未接入，输入会明确标记缺失。模型不自动联网补齐这些事实；所谓后续走势只作为带触发/失效条件的情景，不是准确率经过验证的预测或收益保证。分析文字不作为真实原始数据写入行情导出。

也可以自检：

```powershell
python stock_spider.py --self-test 301307
```

自检只输出采集结果和质量状态，不生成额外导出文件。双击启动脚本时优先使用工程 `.venv`，其次使用 Windows 的 `py` 启动器，最后尝试 `python`。历史新浪日线优先使用 `py-mini-racer` 解码，未安装时可以使用已有的 Node.js，无需为了备用解码重复安装依赖。

离线回归测试不访问行情接口，也不会在工程目录生成导出数据：

```powershell
py -3 -m unittest -q
```

主行情接口并行采集；网络备用请求设有等待上限。接口断开时仍可能改用腾讯备用数据，实际覆盖情况以界面提示及导出的质量状态为准。

腾讯明细出现整批持续网络失败时会停止本次分页并提示中断；已取回部分保留为不完整数据。正常接口仍继续分页至尾页，不会因为记录超过 64 页就截断。

筹码分布为估算口径，不应视为交易所原始持仓数据。不同软件可能使用不同数据源、复权方式、成交口径和更新时间。

导出文件用途：

- `*_daily_indicators.csv`：约两年逐日 OHLCV、前复权/不复权价格、复权因子、接口成交额、历史流通股本、历史行情换手率、历史股本口径计算换手率、盘后成交量/额、理论涨跌停和技术指标；估算金额/换手率仅作备用。东方财富成交额优先，新浪金额补缺并另列跨源差值；`精确历史换手率(%)` 为兼容旧导出的字段名，实际是历史股本口径计算值，不保证交易所精度
- `*_benchmark.csv`：对应宽基指数日线，用于计算相对强弱和超额收益
- `*_intraday.csv`：当日分钟价格、分钟成交量和分钟成交额，含交易阶段与主交易统计标记
- `*_details.csv`：当日逐笔及买卖方向，含序号、交易阶段、记录性质、估算金额与统计标记
- `*_analysis.json`：当前快照、阶段收益、趋势、动量、波动、量价、成交阶段汇总、走势观察和数据质量检查；版本 2 同时记录数据行数、文件清单与缺失的数据集

为了避免生成重复文档，Markdown 报告、单独的成交汇总 CSV 和单独的数据质量 CSV 已停止生成；相应汇总统一保存在 `*_analysis.json` 中。

连续导出使用不同文件名，避免同一秒内重复导出覆盖旧文件。先校验并暂存整批数据，全部文件准备好后才发布，分析 JSON 最后写入；导出异常会回退本批文件，不删除以前的导出。没有取得的数据集不生成空 CSV，缺失项写入 JSON。实时表格仅更新变动单元格或新增行；旧查询和旧行情不会覆盖较新的结果。

已从主界面去掉接口测试和容易混淆的估算筹码展示；未生成额外报告文档。估算字段仍保留在数据中并标记口径，方便有需要时核验。数据质量提示不把缺失当成零，也不把轻微舍入/更新时间差异直接判为数据损坏。

研究分析：先查询股票，再打开“研究分析”点击“查询研究数据”。可切换股票基础、三张财务报表、公司、估值、量价技术、资金市场、仓位风控与综合检查。查询在后台运行，不会自动调用AI，不随实时行情反复抓取财报。切换股票或行情日会丢弃较早研究结果。公开接口失败保留缺失，不编造数据。

已接入东方财富公开财报、公司行业/概念与管理层、估值、实施现金分红、流通股东季报、公告标题、行情商估算资金流、行业指数日线、当日板块榜单与同分类估值对照。行业/估值分类会更新；不同分类层级或相同分类下的业务仍可能不可比。历史行业成分、完整新闻/公告正文、融资融券、机构全部真实持仓、每日北向净买入与预测回测尚未接入。北向相关仅展示公开季报名义持有人，不冒充实际受益人或实时净买入。

原创“现金—成长—估值证据检查 v2”参考郭永清《财务报表分析与股票估值》与彼得·林奇《彼得·林奇的成功投资》所涉及的一般财务、现金流与成长研究原则，不复制书籍原文，不宣称复现作者完整模型或得到作者背书。参考公开介绍：[郭永清课程介绍](https://www.snai.edu/2023/0719/72535.shtml)、[Peter Lynch 出版社介绍](https://www.simonandschuster.com/books/One-Up-On-Wall-Street/Peter-Lynch/9781439126158)。

算法逐项显示带单位的值、期间、启发式阈值和依据，明确区分“通过/需复核/不适用/缺数据”。规则评价率=(通过+需复核)/全部10条；数据取得率按有效输入统计，含亏损导致不适用的已取得数据。二者均不是来源完整率、上涨概率或投资评分。报告期和公告日同时检查；TTM按“本期累计+上年全年−上年同期”计算，现金兑现比较同口径合并净利润，缺同期报表不直接年化。非正利润/基数不计算增长百分比或便宜PEG，改列本期与上年同期金额及增减额。10%资本回报阈值只比较最近年报加权ROE；最新中报/季报ROE另列，不年化、不套全年阈值。非通用金融行业禁用一般负债、流动性、现金兑现阈值。财报勾稽字段不全时提示部分核验，即使已核验部分均通过也不等于财务健康。当前修订版财报不是历史时点数据库，不能据此声称无前视偏差回测。

“情景计算器”提供手填FCFE的DCF股权情景和100股整手简化仓位/盈亏比预算，不自动确定目标价或买卖点，不下单。经营现金减长期资产支出只是简化现金余量，不冒充严格FCFF/FCFE。股权DCF不再扣净负债，永续增长必须低于折现率。个人资金与手填假设不保存、不发送AI；止损预算未考虑费用、跳空、滑点与成交限制。

已查询的研究原始数据、来源日期、缺失情况及算法观察并入已有 `*_analysis.json`，不另生成研究报告文件。AI新分析会接收有界的公开研究快照，老对话仍固定使用原快照；查询研究后请点击重新分析才能纳入。API Key和登录令牌仍不进入股票数据快照。

AI快照优先合并重复口径文字，使用 `annotation_dictionary` 和行内 `note:N` 引用（数值不变）。超过约128 KiB整理目标时，按顺序减少同业/分时/历史明细，保留最新指标、研究观察、TTM/同比计算证据、缺失和质量提示；192 KiB硬性安全上限仍保留。每段注明总行数、实际发送行数及日期范围，`payload.actions`列出进一步精简项；统计在精简前的白名单窗口计算，不把截取的同业子样本当作原样本。预览显示实际发送快照，完整采集和导出不删改。每轮按快照、问题、全部历史及说明实际组成的UTF-8请求正文检查256 KiB上限，中文不按字符数假定字节大小；超限时本地阻止，不自动截掉历史或重试。字节安全上限不代表服务模型的token上下文容量。

AI流式等待：连接/响应头等待仍有上限；数据流总等待默认10分钟，连续无新数据默认120秒，可在AI设置分别调整（总等待0.5～30分钟，无数据5～300秒）。心跳/接收块会重置空闲计时，但不能绕过总时限。界面只显示安全接收进度，不展示隐藏推理，只有确认完整结束才加入回答；超时、失败和取消不自动重试或切换到付费凭据。取消已开始生成的请求不保证免除服务计费。
